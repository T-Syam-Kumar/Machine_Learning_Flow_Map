Before the map

Foundations

The vocabulary everything else is built from.

Paradigm

Supervised Learning

Learn a mapping from input → labeled output. You have the "right answers" during training.

Used for prediction: regression (numbers) & classification (categories).

Paradigm

Unsupervised Learning

Find structure in unlabeled data — no right answers given.

Used for clustering, dimensionality reduction, anomaly detection.

Paradigm

Reinforcement Learning

An agent learns by taking actions in an environment and getting reward/penalty feedback — no fixed dataset.

Used for games, robotics, control systems.

Core tension

Bias–Variance Tradeoff

Bias = error from oversimplified assumptions (underfits). Variance = error from being too sensitive to the training set (overfits).

Total error ≈ Bias² + Variance + irreducible noise. Every model design choice trades one for the other.

Failure modes

Overfitting vs Underfitting

Overfit: low train error, high test error — memorized noise. Underfit: high error on both — too simple.

Fixes: regularization, more/better data, simpler or more complex model, cross-validation.

Practice

Train / Val / Test Split

Never judge a model on data it trained on. Validation set tunes hyperparameters; test set gives the final, honest score.

k-fold cross-validation: rotate the validation fold k times for a more reliable estimate on small data.

Quick flow

Which algorithm do I even use?

Start at the top, follow the branch that matches your problem.

Do you have labeled data (known correct answers)?

YES → Supervised

  • Predicting a numberRegression → Linear / Ridge / Lasso
  • Predicting a category, need to explain whyLogistic Regression → Decision Tree
  • Predicting a category, accuracy over explainabilityRandom Forest → XGBoost
  • Images, text, or sequencesNeural Networks — CNN (images), Transformer (text)

NO → Unsupervised

  • Find natural groups in the dataClustering — K-Means (round groups), DBSCAN (odd shapes + noise)
  • Compress features / visualize high-dim dataDimensionality Reduction — PCA (fast, linear), t-SNE / UMAP (visual, non-linear)
  • Spot rare/unusual pointsAnomaly detection via DBSCAN, Isolation Forest, or Autoencoders
  • Learn from trial-and-error, no dataset at allReinforcement Learning
Line 1

Regression — predicting a number

Origin / baseline

Linear Regression

How Fit a straight line minimizing sum of squared errors (OLS).

Pros
  • Simple, fast, interpretable
  • Coefficients show each feature's effect
Cons
  • Assumes a linear relationship
  • Sensitive to outliers
Evolved from: Linear Regression

Polynomial Regression

Solves Linear regression can't fit curved relationships.

How Add powers of features (x², x³…), still fit linearly on the transformed inputs.

Pros
  • Captures non-linear trends
  • Still simple linear math underneath
Cons
  • High degree → wild overfitting
  • Extrapolates very badly
Evolved from: Polynomial Regression

Ridge Regression (L2)

Solves Many/correlated features make OLS coefficients unstable and overfit.

How Add penalty λΣw² to the loss — shrinks all weights toward zero.

Pros
  • Cuts variance / overfitting
  • Handles multicollinearity well
Cons
  • Keeps every feature (no selection)
  • Adds a λ to tune
Evolved from: Ridge Regression

Lasso Regression (L1)

Solves Ridge shrinks irrelevant features but never removes them.

How Penalty λΣ|w| can push coefficients exactly to zero.

Pros
  • Built-in feature selection
  • Sparse, interpretable models
Cons
  • Unstable with correlated features
  • Can underfit if λ too high
Evolved from: Lasso Regression

Elastic Net

Solves Lasso struggles with correlated feature groups; Ridge won't select features — need both.

How Weighted mix of L1 + L2 penalties.

Pros
  • Selection + stability together
Cons
  • Two hyperparameters to tune
Line 2

Classification — predicting a category

Origin / baseline

Logistic Regression

How Sigmoid of a weighted sum → class probability; trained via log-loss.

Pros
  • Fast, interpretable
  • Calibrated probabilities
Cons
  • Only draws a linear boundary
  • Assumes independent features
Evolved from: Logistic Regression

K-Nearest Neighbors

Solves Real class boundaries are often irregular, not linear.

How Classify by majority vote of the k closest training points. No training phase.

Pros
  • No shape assumptions
  • Naturally multi-class
Cons
  • Slow at prediction on big data
  • Sensitive to scale & noisy features
Evolved from: KNN

Naive Bayes

Solves KNN is slow & memory-heavy at scale — need a fast probabilistic model.

How Bayes' theorem assuming features are conditionally independent given the class.

Pros
  • Extremely fast, tiny data needs
  • Great for text/spam
Cons
  • Independence assumption rarely true
Evolved from: Naive Bayes

Support Vector Machine

Solves Need the most robust boundary possible, plus a way to handle non-linear splits.

How Maximize the margin between classes; kernel trick projects data to separate it non-linearly.

Pros
  • Strong in high dimensions
  • Kernels handle non-linear data
Cons
  • Slow on large datasets
  • Hard to tune, no native probabilities
Line 3

Trees & Ensembles

Origin / baseline

Decision Tree

How Recursively split on the feature/threshold that most reduces impurity (Gini/Entropy).

Pros
  • Fully interpretable "white box"
  • No scaling needed, handles non-linear data
Cons
  • High variance, unstable
  • Overfits easily if grown deep
Evolved from: Decision Tree

Random Forest

Solves A single tree overfits and is unstable.

How Bagging — many trees on random data/feature subsets, then average their votes.

Pros
  • Much lower variance
  • Robust, gives feature importance
Cons
  • Less interpretable, slower to predict
Evolved from: Random Forest

Gradient Boosting

Solves Bagging cuts variance but not bias — trees don't learn from each other's mistakes.

How Build trees sequentially; each new tree fits the residual errors of the ensemble so far.

Pros
  • Usually most accurate tree method
Cons
  • Sequential = slower to train
  • Needs careful tuning / early stopping
Evolved from: Gradient Boosting

XGBoost / LightGBM / CatBoost

Solves Vanilla boosting is slow, unregularized, doesn't scale.

How Regularized, parallelized gradient boosting with smart handling of missing/categorical data.

Pros
  • State of the art on tabular data
  • Fast, regularized against overfitting
Cons
  • Many hyperparameters
  • Less interpretable
Line 4

Neural Networks

Origin / baseline

Perceptron

How Weighted sum of inputs + step activation → one linear decision boundary.

Pros
  • Foundation of all neural nets
Cons
  • Only solves linearly separable problems (fails on XOR)
Evolved from: Perceptron

Multi-Layer Perceptron (MLP)

Solves A single perceptron can't learn non-linear functions.

How Stack layers with non-linear activations (ReLU) + train via backpropagation.

Pros
  • Universal function approximator
Cons
  • Needs lots of data
  • Ignores spatial/sequential structure
Evolved from: MLP

Convolutional Neural Net (CNN)

Solves MLPs need huge parameter counts on images and ignore that nearby pixels relate.

How Shared filters slide over the input to detect local patterns (edges → shapes → objects).

Pros
  • Far fewer params than MLP for images
  • Translation-invariant
Cons
  • Needs lots of labeled data + compute
Evolved from: MLP

Recurrent Neural Net (RNN)

Solves MLPs/CNNs have no memory of previous inputs — bad for sequences.

How A hidden state loops through each time step, carrying past context forward.

Pros
  • Models variable-length sequences
Cons
  • Vanishing gradients forget long-range context
  • Can't parallelize across time steps
Evolved from: RNN

LSTM / GRU

Solves Plain RNNs forget long-term context.

How Gating mechanisms (input/forget/output) learn what to keep or discard over long sequences.

Pros
  • Much longer memory than vanilla RNN
Cons
  • Still sequential, slow to train
Evolved from: LSTM

Transformer

Solves RNN/LSTM process one token at a time — slow, and still lose very long-range context.

How Self-attention lets every token look at every other token in parallel, weighted by relevance.

Pros
  • Parallelizable, fast to train
  • Captures long-range dependencies
Cons
  • Quadratic cost with sequence length
  • Needs huge data/compute from scratch
Line 5

Clustering

Origin / baseline

K-Means

How Pick k centroids, assign points to the nearest one, recompute centroids, repeat.

Pros
  • Fast, simple, scales well
Cons
  • Must pick k upfront
  • Assumes round, equal-sized clusters
Evolved from: K-Means

Hierarchical Clustering

Solves K-Means forces guessing k and assumes spherical clusters.

How Iteratively merge the closest clusters into a tree (dendrogram); cut it anywhere for k clusters.

Pros
  • No k needed upfront
  • Shows structure at every level
Cons
  • O(n²)–O(n³), doesn't scale
Evolved from: Hierarchical

DBSCAN

Solves Prior methods assume blob-shaped clusters and struggle with noise.

How Group densely-packed points; low-density points become outliers.

Pros
  • Arbitrary shapes, auto outlier detection
Cons
  • Struggles with varying density
  • Sensitive to eps / min-points
Line 6

Dimensionality Reduction

Origin / baseline

PCA

Solves Too many features → curse of dimensionality, slow training, hard to visualize.

How Find orthogonal directions of max variance, project onto fewer of them.

Pros
  • Fast, removes correlated noise
Cons
  • Only captures linear structure
  • Components hard to interpret
Evolved from: PCA

t-SNE

Solves PCA's linear projections often make poor 2D visualizations of complex data.

How Match pairwise similarities in high- and low-D space, preserving local neighborhoods.

Pros
  • Excellent cluster visualization
Cons
  • Slow, no new-point projection
  • Loses global structure
Evolved from: t-SNE

UMAP

Solves t-SNE is slow, loses global structure, can't embed new points.

How Manifold-learning based neighborhood preservation, optimized for speed.

Pros
  • Faster, keeps more global structure
  • Can transform new data
Cons
  • Results still hyperparameter-sensitive
Cross-cutting

How models learn: the optimizer chain

Each step fixes a specific pain point of the previous one.

Batch Gradient Descent

Compute the gradient over the whole dataset, then step. Accurate but heavy on large data.

→

Stochastic GD (SGD)

Fixes: full-batch is too slow per step. Update using one/few random samples at a time. Noisier, faster.

→

Momentum

Fixes: SGD zig-zags in narrow ravines. Adds a fraction of the previous update to smooth the path.

→

RMSProp

Fixes: one learning rate doesn't fit every parameter. Adapts rate per-parameter using recent squared gradients.

→

Adam

Fixes: combines Momentum + RMSProp. Default choice for deep learning; fast and robust.

Cross-cutting

Fighting overfitting

Techniques used across almost every model family above.

L1 / L2 penalty

Penalize large weights in the loss function (see Lasso/Ridge).

Dropout

Randomly disable neurons during training so the net can't over-rely on any one path.

Early Stopping

Stop training the moment validation loss starts rising again.

Data Augmentation

Artificially expand training data (crops, flips, noise) so the model generalizes better.

Batch Normalization

Normalize each layer's inputs — stabilizes and speeds up training.

Cross-Validation

Rotate the validation fold to get a more reliable estimate of real-world performance.

Cross-cutting

Evaluation metrics

Pick the metric for the mistake that actually costs you.

Classification
Accuracy% correct overall — misleading on imbalanced classes.
PrecisionOf predicted positives, how many were right. Use when false positives are costly.
RecallOf actual positives, how many were caught. Use when false negatives are costly (e.g. disease screening).
F1-scoreHarmonic mean of precision & recall — good single number for imbalanced data.
ROC-AUCHow well the model ranks positives above negatives across all thresholds.
Confusion MatrixGrid of true/false positives/negatives — the source all the above are built from.
Regression
MAEMean absolute error — average size of mistakes, in original units, robust to outliers.
MSEMean squared error — penalizes big mistakes much more heavily.
RMSE√MSE — back in original units, still punishes large errors.
R²Fraction of variance explained by the model (1.0 = perfect, 0 = no better than the mean).
